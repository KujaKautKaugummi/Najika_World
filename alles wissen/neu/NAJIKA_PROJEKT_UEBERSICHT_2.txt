## NAJIKA - Projekt-Übersicht

### Architektur-Übersicht
NajikaCore ist eine **web-basierte virtuelle Companion-Anwendung** mit folgenden Komponenten:

```
┌─────────────────────────────────────────────┐
│  Python HTTP Server (najika_server.py)     │
│  - AI Integration (Ollama/Cloud)            │
│  - State Management + Persistence           │
│  - Battle/Minigame APIs                     │
└──────────────┬──────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────┐
│  Three.js 3D Frontend (digivice/)          │
│  - 12 Räume mit KayKit Assets              │
│  - 3 Kamera-Modi (Orbit/Third/First)       │
│  - Character Controls (Skeleton Mage)       │
│  - 7 Minigames                              │
└─────────────────────────────────────────────┘
```

---

## Backend: najika_server.py (467 Zeilen)

### Server-Kern
- **HTTP Server**: `ThreadingHTTPServer` für parallele Request-Verarbeitung
- **Port**: 8000 (konfigurierbar via `.env`)
- **CORS**: Vollständig aktiviert

### AI-System
**Persona**: Najika mit 4 Facetten (MEGUMIN, HARLEY, SHIRO, MELISSA)
- **Primär**: Ollama local (`najika-local` model)
- **NSFW Mode**: `najika-wizard` (Trigger: Keyword "kätzchen")
- **Cloud Option**: OpenAI/Anthropic (PIN-geschützt)
- **Response Caching**: LRU-Cache (100 Einträge, 1h TTL)
- **Context Window**: Letzte 4 Messages

### Persistence-System
- **Auto-Save**: Alle 30 Sekunden
- **Backup-Rotation**: 3 letzte Backups
- **Save-Location**: `saves/najika_state.json`
- **Gespeicherte Daten**: History, Battle-State, User-Stats, Progress

### Battle-System
- **HP**: 100 (Start)
- **Wellenbasiert**: Gegner-Anzahl = 2 + wave
- **Schadensberechnung**: damage = max(0, enemies - 1)
- **Gegnertypen**: Rats, Skeletons, Slimes

### API-Endpunkte (20+)
```
GET /health                  → Server-Status
GET /api/rooms               → Raum-Liste
GET /api/status              → State inkl. Private-Mode
GET /api/status/stream       → SSE für Live-Updates
GET /api/cache/stats         → Cache-Statistiken

POST /api/chat               → AI-Nachricht senden
POST /api/battle/start       → Kampf initialisieren
POST /api/battle/attack      → Angriff ausführen
POST /api/minigame/*         → Minigame-Scores
POST /api/heal               → HP auf 100 setzen
POST /api/user/update        → User-Stats speichern
```

## Frontend: digivice/

### 3D-Engine (3d_scene.js - 1037 Zeilen)

**Kamera-Modi:**
- **Orbit**: Frei drehbare Kamera um Character
- **Third-Person**: Folgt Character von hinten
- **First-Person**: Ego-Perspektive

**Character-System:**
- **Model**: Skeleton_Mage.glb (KayKit Skeletons Pack)
- **Waffe**: Wand (procedural attached)
- **Speed**: 7.5 units/s
- **Controls**: WASD/Arrows

**Room-Building:**
- **Dynamic Loading**: KayKit GLTFs
- **Floor/Wall/Props**: Modulares System
- **Frustum Culling**: Optimierung für große Räume
- **Fallback Mode**: Prozeduraler Raum wenn Assets fehlen

**Lighting:**
- Ambient + Directional + 2x Point Lights
- Per-Room Color Palettes
- Private-Mode Override (rotes Schema)

## Starten der Anwendung

```batch
START_NAJIKA.bat
```

**Start-Sequence:**
1. Prüft Ollama-Verfügbarkeit
2. Startet Python-Server auf Port 8000
3. Lädt gespeicherten State (falls vorhanden)
4. Initialisiert AI-Provider
5. Frontend erreichbar unter `http://localhost:8000/`

## Technische Highlights

### Performance-Optimierungen
- **Frustum Culling**: Props >60 units werden ausgeblendet
- **PixelRatio Cap**: Max 2x für mobile Devices
- **Lazy Asset Loading**: Nur benötigte Räume
- **Response Caching**: Reduziert AI-Calls

### Robustheit
- **Fallback Room**: Prozeduraler Raum wenn Assets fehlen
- **Auto-Save**: Verhindert Datenverlust
- **SSE Reconnection**: Automatisches Wiederverbinden
- **Backup-Rotation**: Letzte 3 States erhalten

### Features
- **Private Mode**: Visuelle Indikation + Model-Switch
- **Webcam Integration**: Optional aktivierbar
- **Cloud AI Toggle**: PIN-geschützt
- **Dungeon Levels**: 10 verschiedene Schwierigkeitsstufen
